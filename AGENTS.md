# AICosy project conventions

Follow the user's global development rules. This repository implements a behavioral preference experiment, with no sexual media and no inference of subjective pleasure.

- Start with README.md (Chinese: README.zh-CN.md). Current contract: docs/v4-contract.md; V3/V2/V1 archives: docs/v3-experience-design.md, docs/v2-contract.md, docs/implementation-contract.md. External protocols: docs/http.md and docs/connectors.md.
- Python 3.11+, standard library runtime; do not add dependencies without user authorization.
- `aicosy/engine.py` dispatches by stored engine version. `engine_v4.py`/`dynamics_v4.py` own current rules and checkpoints; V1–V3 modules preserve historical replay. Do not alter old transition outputs when changing new behavior. `aicosy/service.py` owns identities, SQLite transactions, activity and persistence. Adapters delegate transitions to the service. Clients use the public HTTP protocol. `aicosy/web/` is the single static observer source and packaged asset location.
- Preserve strict state versions, ordered events, normal observation blinding, model identity separation, and research labels. The human observer at / reads persisted visible state, /status preserves the lamp-only view. Never simulate player activity or label a rule script as a verified model. `observer.py` is a read-only projection and has no game mutations. Profiles/reset/metrics are separated by engine version and normal/research mode. Profile reset keeps raw logs; changes to event formats require persistence compatibility planning.
- Choose directly related small headless unittest modules; current V4 baseline is `python3.11 -m unittest tests.test_continuous_engine tests.test_continuous_service -v`. Add protocol/compatibility checks when affected. Do not add broad UI/stress tests, launch browsers, or copy the project for validation. Temporary test databases must be cleaned up.
- Demo evidence is a scripted player's behavior. Never label a scripted or mock-model run as a commercial model experiment. Record unavailable hidden activations honestly.
- Public-facing name: AICosy. Keep historical engine outputs and stored data compatible; new commands and configuration use `aicosy-*` and `AICOSY_*` with legacy aliases where needed.
- Before publishing, inspect both Git author/committer metadata and tracked file/package attribution. Use the repository-scoped project identity rather than inheriting a workstation's personal or team identity. Never publish personal identifiers as examples or in cleanup notes.
- Public author and copyright attribution is exactly `aicosy team`. Keep account identifiers, personal contact information and workstation paths out of public documentation and examples.
