# 人类观察页

入口为 `/`，`/observer` 为同页别名；原来的纯圆灯页保留在 `/status`。页面只读，不替 AI 提交动作，也不会给会话续心跳。

## 当前证据与改动

原页面 `web/status.html` 只有服务活动圆灯，无法显示是哪一个玩家、处于哪个回合、怎样改变世界、是否已结束，也不提供历史会话入口。新增观察页直接读取服务端投影，显示真实会话和保存的过程；无会话、无活动和断线分别表达。

## 参考与采用的规则

- [TensorBoard 官方 Graphs 指南](https://www.tensorflow.org/tensorboard/graphs)：以概念图为主要内容，通过节点选择查看局部信息。本页让真实机器图占据中央；节点详情保持在图下方，不为每个节点制造卡片。
- [NetLogo 官方 BehaviorSpace 指南](https://docs.netlogo.org/behaviorspace.html)：观察模型运行时，运行状态、过程与记录需要明确对应。本页让回合、当前区域、行动日志和逐拍过程来自同一会话；已经记录的过程播放明确标记为“记录回放”。

采用暖黑色底、轻边界分区和克制的琥珀/青色。左侧整行可选择游玩记录，中央显示世界和信号过程，右侧显示最新行动及其参数。没有随机动画、假 AI 活动、快乐分数、模型自述推断或游戏控制按钮。

## 数据与交互边界

- `/v1/observer/sessions` 提供会话列表、服务真实状态和推荐初始选择；`/v1/observer/sessions/{id}` 提供正常观察投影及按序事件。
- 默认选择服务端推荐会话。用户手动选择后保留选择，并用 `?session=...` 提供可返回的记录链接。
- 视图区分“实时”“暂停”“历史记录”。接入类型由接入方声明，页面不将脚本标为自主模型。
- 信号热图只显示服务实际返回的 `frames[].values`。本地“播放记录”只移动记录中的拍数，不改变游戏；不会伪造 AI 持续游玩。
- 付费重演可能对应旧图，故默认用 `performance.machine` 绘制该过程；“查看当前结构”明确切换回最新结构，当前结构视图不套用旧过程的信号颜色。
- 旧版记录没有逐拍过程时，仍可查看已有创造图、已发现序列或信号内容，并标为“旧版记录”。
- API 请求只发送同源路径。Bearer 令牌从 URL fragment 读取后从地址栏清除，仅保留在闭包内；不写入 query、日志或浏览器存储。全部动态字符串用 DOM `textContent` 输出。
- 切换会话会取消旧详情请求；返回顺序也经过请求序号和选择版本校验，旧响应不会覆盖新选择。超时和连接失败清除实时状态，保留已接收记录并自动重试。
